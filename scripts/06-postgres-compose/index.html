BOUNDARY

只讓這部電腦連入

ports:
  - "127.0.0.1:55432:5432"

左邊是 host IP + port，右邊是 container port。明寫 127.0.0.1，避免預設綁到所有 interfaces。

公開 demo credential：playback_demo / playback_demo_password_change_me。它只供這個 loopback spike；不得複製到 production、LAN 或其他服務。

OPERATE

用五個 bounded actions 學習

  1. Check
    CLI、Compose syntax、engine
  2. Start
    啟動並等 healthy
  3. Status
    觀察 running / health
  4. Query
    寫 demo data、JOIN、EXPLAIN
  5. Stop
    停 container，保留 volume
.\study.ps1
.\study.ps1 -Action Start
.\study.ps1 -Action Status
.\study.ps1 -Action Query
.\study.ps1 -Action Stop

沒有 Reset。停止 process 與刪除 data 是兩件事；教學腳本不把破壞性操作包成捷徑。

  • PK：唯一且 non-null；可被其他 table 引用。

QUERY SAFETY

Value 與 SQL 分開

await using var command = dataSource.CreateCommand(
    "SELECT title FROM lecture_sessions WHERE id = $1");
command.Parameters.Add(new() { Value = sessionId });

$1 是 value placeholder。不要用字串插值把 session id、title、transcript 或 user question 拼入 SQL。Table/column name 不能用 value parameter 代替；若需要動態 identifier，要用固定 allowlist。

Npgsql 官方 parameters 指引

EVIDENCE

不要只看「container 跑了」

  1. Start 要等 healthcheck，而不是只等 process created。
  2. Query 應顯示 JOIN 出來的 session/chunk/transcript。
  3. 重跑 Query 會用新 UUID，不會破壞前一次資料。
  4. Stop → Start 後舊 rows 仍存在，證明 volume persistence。
  5. 用 docker compose config 核對 port 仍是 loopback。
為甚麼 tiny dataset 未必使用 index？

Query planner 估計掃描幾列比走 index 更便宜時，會合理選 sequential scan。Index 是否值得，要用接近真實資料量的 EXPLAIN (ANALYZE, BUFFERS) 驗證；本 spike 只先學讀 plan，不做 performance claim。
