0. 點解獨立一課？

《C# 中階銜接》第 1 節教嘅 method 淨係得一個參數、一句 return——夠用嚟入門，但真正寫 lecture-note app 嗰陣，method 好快就會需要：回傳多過一個值（out）、畀個「唔強制填」嘅參數（optional parameter）、接受數量不定嘅輸入（params），或者同名但唔同參數嘅版本（overload）。呢頁會將呢啲全部拆開講清楚，仲會加埋 local function 同 recursion——兩個之後喺 pipeline 教學（例如整理 transcript、遞迴處理巢狀資料）會不斷見到嘅寫法。

建議你已經睇完《C# 中階銜接》第 1 節，識最基本嘅 static method 結構同 expression-bodied 語法。呢頁唔會再由零教「乜嘢係 method」。

1. Method 結構回顧

一個 method 由「修飾詞、回傳型別、名、參數列、body」五部分組成；如果 body 淨係一句 return，可以用 => 寫做 expression-bodied，兩種寫法完全等價：

static int Square(int number)
{
    return number * number;
}

// 等價，expression-bodied 寫法：
static int Square(int number) => number * number;

之後所有例子都會延續呢個樣式，逐步加入新概念——參數列會由一個變到多個，body 會由一句變到有 if、迴圈、甚至自己入面再包一個 method。

2. 參數傳遞：value／ref／out／in

C# 有四種方式將參數傳入 method，決定咗「method 入面改嗰個參數，會唔會影響返出面個變數」：

方式關鍵字method 入面改動呼叫者要唔要預先畀值
By value（預設）（冇）唔會影響出面要
By referenceref會影響出面要
Outputout會影響出面（method 一定要賦值）唔使
Read-only referencein唔會影響出面（method 唔准改）要

By value（預設）：method 攞到嘅係一份複本

冇寫任何關鍵字嘅參數，預設就係 by value——method 攞到嘅係呼叫者個值嘅複本，喺 method 入面點改都好，出面個變數完全唔受影響（呢個同第 7 節「value type vs reference type」講嘅「複製值」係同一個原理）：

static void TryDouble(int number)
{
    number = number * 2;   // 淨係改咗呢個複本
}

int count = 5;
TryDouble(count);
Console.WriteLine(count);   // 5，count 完全冇變

ref：傳返個「路牌」入去，method 可以改到出面個變數

加咗 ref 之後，method 攞到嘅唔再係複本，而係直接指去呼叫者個變數——method 入面改咗，出面即刻見到。ref 一定要喺參數宣告同呼叫兩個位都寫，唔可以淨寫一邊：

static void AddBonusSeconds(ref double duration)
{
    duration += 5;
}

double duration = 10;
AddBonusSeconds(ref duration);
Console.WriteLine(duration);   // 15

用 ref 之前，呼叫者一定要已經畀咗個初始值（好似上面 double duration = 10;），因為 method 唔保證一定會賦新值畀佢。

out：專門用嚟「回傳多過一個值」

《C# 中階銜接》其實你已經見過 out——int.TryParse(input, out int value) 就係呢個 pattern。out 同 ref 好似，都係傳「路牌」入去，分別係：out 唔使呼叫者預先畀值，但換嚟一個規矩——method 一定要喺每一條執行路徑入面幫個 out 參數賦值，否則 build 唔到。用 out 嚟自己寫一個「拆返兩個值出嚟」嘅 method：

static bool TrySplitName(string fullName, out string firstName, out string lastName)
{
    string[] parts = fullName.Split(' ');
    if (parts.Length != 2)
    {
        firstName = "";
        lastName = "";
        return false;
    }

    firstName = parts[0];
    lastName = parts[1];
    return true;
}

bool ok = TrySplitName("Ada Lovelace", out string first, out string last);
Console.WriteLine($"{ok}: {first} / {last}");   // True: Ada / Lovelace

呢個「回傳 bool 表示成功與否，實際結果用 out 帶出嚟」就係 C# 標準函式庫成日用嘅 TryXxx pattern——好處係唔使靠拋例外（exception）嚟表達「呢個輸入唔啱格式」呢類預期之內嘅失敗。

in：讀取用嘅 reference，唔准改

in 都係傳「路牌」入去（避免複製一大份資料嘅效能開銷），但 method 入面唔准修改佢——寫嘗試修改 in 參數會喺 build 時報錯。呢個主要係為咗大型 struct 值嘅效能優化（唔使複製一大份 struct 落去 method），日常寫 lecture-note app 呢類專案幾乎用唔著，見到知係咩就夠。

3. Optional parameters 同預設值

參數可以畀一個預設值，變成 optional——呼叫者可以唔理佢，method 就會用返個預設值：

static string FormatDuration(double seconds, string unit = "s") => $"{seconds}{unit}";

Console.WriteLine(FormatDuration(14.8));          // 14.8s
Console.WriteLine(FormatDuration(14.8, "sec"));   // 14.8sec

規則：optional parameter 一定要排喺所有 required parameter 之後——(string unit = "s", double seconds) 呢種寫法唔合法，因為 compiler 冇辦法判斷「跳過咗邊個」。

4. Named arguments

正常呼叫 method 係跟參數列嘅次序（positional）；但都可以用「參數名: 值」嘅寫法，噉就可以打亂次序，令有多個 optional parameter 嘅呼叫更加清楚：

Console.WriteLine(FormatDuration(unit: "sec", seconds: 14.8));   // 14.8sec，次序調轉都冇問題

Named argument 對「一睇個名就知呢個位傳緊咩」特別有用，例如一堆 bool 參數嘅呼叫，單靠位置好難分辨邊個係邊個；配合具名，可讀性即刻提升。

5. params 陣列

params 令一個參數可以接收「零個、一個，或者任意多個」引數，method 入面會當佢係一個陣列嚟用：

static double SumDurations(params double[] seconds)
{
    double total = 0;
    foreach (var s in seconds)
    {
        total += s;
    }

    return total;
}

Console.WriteLine(SumDurations(14.8, 15.0, 4.2));   // 34
Console.WriteLine(SumDurations());                   // 0，冇傳任何引數都合法

params 只可以用喺參數列嘅最後一個位置，一個 method 最多只可以有一個 params 參數。呼叫嗰陣，你亦都可以直接傳一個現成嘅陣列入去（SumDurations(myArray)），效果一樣。

6. Method overloading

Overloading 即係幾個 method 用同一個名，但參數列（型別和／或數量）唔同。Compiler 會喺 compile time（唔係 runtime）根據你傳嘅引數型別，揀返啱嗰個版本嚟用：

static string Describe(int count) => $"{count} chunks";
static string Describe(string text) => $"text: {text}";

Console.WriteLine(Describe(5));        // 5 chunks
Console.WriteLine(Describe("hello"));  // text: hello

唔淨係睇返回型別：單靠「返回型別唔同」唔算 overload——參數列（型別、數量或者順序）一定要有分別。static int Foo() 同 static string Foo() 呢兩個放埋一齊會喺 build 時報錯，因為 compiler 揀 overload 嗰陣淨係睇你「點樣呼叫」（傳咗咩引數），唔會理你之後點用個返回值。

因為揀邊個 overload 係 compile time 就決定咗，所以喺 IDE 打 Describe( 嗰刻，只要你輸入緊個引數，IDE 已經可以即時話你知會叫緊邊一個版本、提示緊邊個型別——呢個係 static typing 帶嚟嘅其中一個著數。

7. Local function

Local function 係一個定義喺另一個 method body 入面嘅 method，淨係嗰個外層 method 先叫得到佢，好處係唔會污染成個 class／檔案嘅 method 列表——啱用嚟寫一啲淨係嗰度先用得著嘅小型 helper。Local function 可以直接讀到外層 method 嘅變數（呢個叫 closure）：

static List<string> BuildNoteLines(List<string> texts)
{
    var lines = new List<string>();
    int index = 1;

    foreach (var text in texts)
    {
        if (IsUseful(text))
        {
            lines.Add($"{index}. {text}");
            index++;
        }
    }

    return lines;

    bool IsUseful(string candidate) => !string.IsNullOrWhiteSpace(candidate);
}

IsUseful 定義喺 return 之後，但一樣用得——local function 唔似 top-level statements 話「輔助 method 一定要放最尾」咁死板，C# 會喺 build 時掃描成個外層 method body，唔理你將 local function 寫喺頭定尾。習慣上會擺喺最後，等主要邏輯行先睇到。

同攞出去做獨立 private static method 比較：如果 IsUseful 淨係 BuildNoteLines 用得著，寫做 local function 可以清楚表達「呢個 helper 唔屬於任何其他地方」，同埋唔使額外傳個 texts 或者 index 落去（因為 closure 已經睇到）。

8. Recursion

Recursion（遞迴）即係一個 method 喺自己 body 入面再呼叫自己。寫法一定要有兩部分：base case（唔使再遞迴、直接有答案嘅情況）同 recursive case（將問題拆細，再交返畀自己處理）。經典例子——階乘：

static long Factorial(int n) => n <= 1 ? 1 : n * Factorial(n - 1);

Console.WriteLine(Factorial(5));   // 120

拆開睇：n <= 1 就係 base case（0! 同 1! 都定義做 1，唔使再遞迴）；否則就係 recursive case——n * Factorial(n - 1)，將「計 n 嘅階乘」拆做「n 乘以計 n-1 嘅階乘」，每叫一次個問題就細一步，最終一定會撞到 base case 停低。

留意 stack 深度：每次遞迴呼叫都會喺 call stack 開多一層；如果 base case 寫錯（或者輸入太大、遞迴太深），會撞到 StackOverflowException，甚至令成個程式即時崩潰（呢個例外唔似其他 exception 咁可以用 try/catch 救返）。一般迴圈（for／foreach）冇呢個限制，處理巨大或者深度不定嘅資料時，往往迴圈比遞迴穩陣。

9. 動手練習

估下輸出 1：overload resolution

唔好即刻跑，先估下呢兩句會印咩：

static string Describe(int count) => $"{count} chunks";
static string Describe(string text) => $"text: {text}";

Console.WriteLine(Describe(5));
Console.WriteLine(Describe("hi"));

答案：5 chunks 同 text: hi。Compiler 喺 compile time 就已經根據引數型別（int 定 string）決定咗叫邊一個 Describe 版本，唔使等到 runtime 先揀。

估下輸出 2：by value vs ref

兩個版本睇落好似，估下輸出會唔會一樣：

static void AddBonusSecondsByValue(double duration)
{
    duration += 5;
}

static void AddBonusSecondsByRef(ref double duration)
{
    duration += 5;
}

double a = 10;
AddBonusSecondsByValue(a);
Console.WriteLine(a);

double b = 10;
AddBonusSecondsByRef(ref b);
Console.WriteLine(b);

答案：10 同 15。AddBonusSecondsByValue 攞到嘅係 a 嘅複本，method 入面加 5 淨係改咗嗰份複本，a 出面完全冇變；AddBonusSecondsByRef 因為有 ref，直接指去 b 本身，加 5 之後出面即刻見到 15。

自己動手：平均錄音長度

已經幫你喺 demo/csharp-practice/concepts/03-methods-practice.cs 準備咗 TODO 骨架。目標：寫一個 static double AverageDuration(params double[] seconds) method——

  • 陣列冇任何元素（空陣列）就回傳 0，避免除以零；
  • 否則回傳所有數值嘅平均數（總和除以個數）。

喺 top-level statements 分別試 AverageDuration(14.8, 15.0, 4.2) 同 AverageDuration()，印出結果。

cd demo/csharp-practice
dotnet run concepts/03-methods-practice.cs

答案：

Console.WriteLine(AverageDuration(14.8, 15.0, 4.2));  // 11.333333333333334
Console.WriteLine(AverageDuration());                  // 0

static double AverageDuration(params double[] seconds)
{
    if (seconds.Length == 0)
    {
        return 0;
    }

    double total = 0;
    foreach (var s in seconds)
    {
        total += s;
    }

    return total / seconds.Length;
}
