0. 點解獨立一課？

《C# 中階銜接》第 1 節嘅三行表已經夠你跟住第 2 節寫 record LectureChunk，但呢三個關鍵字背後嘅分別遠遠唔止「預設比較方式」咁簡單——仲牽涉緊 constructor 點寫、property 可唔可以改、複製嗰陣係複製緊個 object 定係複製緊份值、可唔可以畀其他型別繼承。呢啲分別揀錯咗，輕則行為古怪，重則好似 Dictionary key 用錯型別咁樣，令 lookup 完全失效。呢頁會逐個攤開，最後仲會補埋 record struct——一個 record 同 struct 嘅混合體，第 1 節嘅表冇提過。

建議你已經睇過 《型別與變數》深入教學，尤其係 第 7 節 value type vs reference type——呢頁成套內容都建立喺嗰個分別之上。

1. Class 基礎：有身分、會變化嘅嘢

class 係 reference type（見 型別教學第 7 節）。佢啱用喺一樣有持續身分（identity）、狀態會隨時間合理咁變化嘅嘢——例如一個「錄音緊定未」嘅 session 控制器：

public sealed class RecordingSession
{
    private bool _isRecording;

    public Guid SessionId { get; }

    public RecordingSession(Guid sessionId)
    {
        SessionId = sessionId;
    }

    public bool IsRecording => _isRecording;

    public void Start() => _isRecording = true;
    public void Stop() => _isRecording = false;
}

var session = new RecordingSession(Guid.NewGuid());
session.Start();
Console.WriteLine(session.IsRecording);   // True

逐個部分：

  • private bool _isRecording;——一個 field，屬於呢個 object 嘅內部狀態，慣例用 _camelCase 命名同埋 private（唔畀外面直接改）。
  • public Guid SessionId { get; }——一個 property，冇寫 set，即係只可以喺 constructor 度賦值一次，之後唔可以再改（叫 get-only property）。
  • public RecordingSession(Guid sessionId) { ... }——constructor，同 method 名一樣叫做個 type 名，冇回傳型別；new RecordingSession(...) 嗰陣會執行呢段 code。
  • Start()／Stop()——一般 method，會改動 object 內部嘅 _isRecording，呢個係 class 同下面 record 最大分別：class 嘅 instance 通常容許喺原地變化（mutate in place）。

呢個 session 由頭到尾都係同一個 object——你 Start() 完佢，唔會變成一個新 RecordingSession，而係同一個 object 入面嘅 _isRecording 由 false 變咗 true。呢種「有一個持續身分，狀態逐步演變」嘅模型，就係 class 存在嘅理由。

2. Record 詳解：以資料為中心、預設 immutable

《C# 中階銜接》第 2 節已經用過 positional record：

public sealed record LectureChunk(Guid SessionId, long Sequence, string Text, double DurationSeconds);

Record 除咗可以淨係聲明個「形狀」，仲可以有 body，加多啲計算出嚟嘅 property：

public sealed record LectureChunk(Guid SessionId, long Sequence, string Text, double DurationSeconds)
{
    public string Summary => $"{Sequence}: {Text}";
}

Summary 唔係建構時傳入嘅資料，而係每次讀取都即時由 Sequence／Text 計出嚟嘅衍生值——呢個寫法同 class 嘅 expression-bodied property 一樣。

另一種寫法：init-only property（唔用 positional）

如果唔想用 positional 寫法（例如欄位多、想個別加 default 值），可以直接寫 property，配合 init：

public sealed record LectureNote
{
    public required string Title { get; init; }
    public string Body { get; init; } = "";
}

var note = new LectureNote { Title = "Week 1", Body = "CAP theorem" };
// note.Body = "changed";   // Compiler error: init-only，建立完就唔可以再賦值

init 同 get-only（{ get; }）好似，分別係 init 容許用 object initializer 語法（new LectureNote { Title = ... }）喺建構嗰刻賦值，之後就同 get-only 一樣唔可以再改。required（C# 11 開始）逼使 caller 一定要喺 object initializer 度提供呢個欄位，否則 compile 唔過——呢個係喺冇用 positional constructor 嗰陣，補返「唔可以漏傳資料」呢個保障嘅方法。

兩種寫法（positional／init-only）建構出嚟嘅 object 都係一樣 immutable。with-expression 同 value equality（== 比較所有 property 值）喺《中階銜接》第 2 節已經示範過，呢頁唔重複，第 5 節會再深入 equality 嘅底層原理。

3. Record class vs record struct

你寫 record LectureChunk(...)，其實係 record class LectureChunk(...) 嘅簡寫——record 預設係 reference type（同 class 一樣，heap allocate）。由 C# 10 開始，你可以寫 record struct，攞到 record 嘅自動 equality／ToString()／with，但複製行為同一般 struct 一樣係 value type：

public readonly record struct AudioLevel(double Rms, bool IsSpeech);

var a = new AudioLevel(0.02, false);
var b = a;   // 完整複製一份值，唔係指去同一個 object

AudioLevel 代表 VAD（module 02）每一幀 audio 量度出嚟嘅 energy 讀數（RMS 值）同埋判斷結果——三小時錄音可能每幾十毫秒就產生一個呢種讀數，數量以萬計，而且用完即棄，冇任何一個讀數需要獨立嘅「身分」，正正係 record struct 想解決嘅場景。readonly 呢個修飾詞令 AudioLevel 嘅 property 全部係 get-only（同 record class 嘅 init 效果對齊）。如果淨係寫 record struct AudioLevel(double Rms, bool IsSpeech);（冇 readonly），positional property 預設會係可變嘅 { get; set; }，同 record class 預設 { get; init; } 唔同——呢個係初學者常見誤會位，記住：想要一個真正 immutable 嘅 record struct，一定要自己加 readonly。

情況建議
細、複製頻繁、冇必要有身分嘅資料用 readonly record struct——例如上面嘅 AudioLevel，每幀都新建一個、冇人會記住「呢個係邊一個 AudioLevel」
大啲嘅資料、或者概念上應該由多處共享同一份參照用預設嘅 record（record class）——例如呢個 app 嘅 LectureChunk、LectureNote

4. Struct 基礎同 mutable struct 陷阱

struct 係 value type（同 型別教學第 7 節提過嘅 int 同一類）：賦值、傳參、放入 foreach 變數，全部都係複製一份完整獨立嘅值，唔係指去同一份資料。呢個特性配合可變（mutable）嘅 struct 就會整出一個經典初學者陷阱——想像你想將一批 VAD energy 讀數入面，太細聲嘅一律重新標記做「唔係人聲」：

public struct RawAudioLevel
{
    public double Rms;
    public bool IsSpeech;
}

var readings = new List<RawAudioLevel> { new RawAudioLevel { Rms = 0.01, IsSpeech = true } };

foreach (var reading in readings)
{
    if (reading.Rms < 0.02)
    {
        reading.IsSpeech = false;   // 諗住標低太細聲嘅讀數，只改到 foreach 變數嗰個 copy
    }
}

Console.WriteLine(readings[0].IsSpeech);   // 依然係 True，list 入面嗰個冇變過！

點解會咁：foreach 入面嘅 reading 係 readings[0] 嗰份值嘅一份複製，唔係一條指去 readings[0] 嘅參照——因為 RawAudioLevel 係 value type。reading.IsSpeech = false 呢句完全合法，冇任何 compiler 警告，但佢改嘅係 reading 呢個獨立複製品，同 readings list 入面嗰個原本嘅值完全冇關係——如果呢個 VAD gate 真係咁寫，太細聲嘅讀數永遠都唔會被重新標記，靜音都會被當人聲送去 ASR。

呢個唔係 bug，係設計上嘅風險：正因為 mutable struct 好容易整出「睇落改咗、其實冇改到」嘅程式碼，普遍建議係：如果要寫 struct，就寫成 readonly struct（所有 field 一律 readonly，逼你用 with 或者重新 new 嚟產生新值，而唔係原地改）；又或者直接用第 3 節嘅 readonly record struct，一步到位攞埋自動 equality。

5. Equality 深入：呢個係最多人估錯嘅位

Class：預設係 reference equality

冇 override 嘅 class，== 同 .Equals() 兩個都係比較「係唔係同一個 object」，唔理內容：

public class ChunkLabel
{
    public string Text = "";
}

var a = new ChunkLabel { Text = "intro" };
var b = new ChunkLabel { Text = "intro" };

Console.WriteLine(a == b);        // False，兩個獨立 object，就算內容一樣
Console.WriteLine(a.Equals(b));   // False，同一個原因

Record（record class 或 record struct）：編譯器自動生成 value equality

public sealed record ChunkLabelRecord(string Text);

var ra = new ChunkLabelRecord("intro");
var rb = new ChunkLabelRecord("intro");

Console.WriteLine(ra == rb);        // True，逐個 property 比較內容
Console.WriteLine(ra.Equals(rb));   // True

Plain struct（唔係 record）：.Equals() 有，但 == 未必有

呢度係最容易搞錯嘅位：struct 嘅 .Equals(object) 係由 System.ValueType 繼承嚟嘅，會用 reflection 逐個 field 做 value 比較（work，但慢）。但 == operator 唔會自動生成——如果你冇自己寫 operator ==，直接寫 p1 == p2 會喺 build 嗰刻報 CS0019：

public struct RawAudioLevel
{
    public double Rms;
    public bool IsSpeech;
}

var a1 = new RawAudioLevel { Rms = 0.02, IsSpeech = true };
var a2 = new RawAudioLevel { Rms = 0.02, IsSpeech = true };

Console.WriteLine(a1.Equals(a2));   // True，ValueType 用 reflection 逐個 field 比較
Console.WriteLine(a1 == a2);        // Compiler error CS0019：RawAudioLevel 冇定義 == operator

如果由其他語言（例如 Python 嘅 @dataclass，== 通常隨手就有）過嚟，呢個係好常見嘅意外。想要 plain struct 支援 ==，就要自己寫 public static bool operator ==(RawAudioLevel a, RawAudioLevel b)（同埋對應嘅 !=），呢頁唔展開手寫做法——直接用 record struct 就自動攞晒。

Record struct：同 record class 一樣，== 同 .Equals() 都自動生成

public readonly record struct AudioLevel(double Rms, bool IsSpeech);

var r1 = new AudioLevel(0.02, true);
var r2 = new AudioLevel(0.02, true);

Console.WriteLine(r1 == r2);        // True
Console.WriteLine(r1.Equals(r2));   // True

總結表

型別預設 ==預設 .Equals()
class（冇 override）Reference equalityReference equality（繼承自 object）
record（record class）Value equality（編譯器生成）Value equality（編譯器生成，並實作 IEquatable<T>）
struct（plain，非 record）未定義——直接用會係 CS0019 compile error，除非自己寫 operator ==Value equality（繼承自 ValueType，reflection 實作，較慢）
record structValue equality（編譯器生成）Value equality（編譯器生成）

牢記呢條規矩：如果你手動 override Equals()，就一定要同時 override GetHashCode()。兩個「相等」嘅 object 如果 hash code 唔一致，喺 Dictionary／HashSet 呢類靠 hash bucket 分類嘅集合入面會查唔到——表面睇落 Equals 冇錯，但整個 lookup 已經悄悄壞咗。record／record struct 會自動幫你同步生成呢兩個，唔使自己記。

6. Inheritance 簡介

Class：單一繼承 + 多個 interface

class 可以繼承一個 base class（單一繼承），同時實作任意多個 interface：

public class Base
{
    public virtual string Describe() => "base";
}

public class Derived : Base
{
    public override string Describe() => "derived";
}

sealed（第 2 節 LectureChunk 一直都有用）令一個 class／record 唔可以再被繼承。呢兩份教學入面自訂型別預設都寫 sealed：喺未有實際需要俾其他型別繼承之前，sealed 係更安全嘅預設值——一來避免將來有人喺完全冇諗過嘅情況下繼承你嘅型別、令行為變得難以推斷；二來 sealed 型別喺某啲場景（例如 equality 比較）仲有少少效能著數。

Record：都可以繼承，包括 positional record

public record BaseChunk(Guid SessionId);
public record LectureChunk(Guid SessionId, string Text) : BaseChunk(SessionId);

LectureChunk 繼承 BaseChunk，並將 SessionId 傳返俾 base record 嘅 constructor——寫法同 class 繼承時要 call base(...) 意思一樣。呢個機制存在，但呢頁唔深入（例如多層 record 繼承嗰陣 equality 點運作），記住「record 都可以繼承」就夠。

Struct：唔可以繼承（但可以實作 interface）

struct（plain 或 record struct）唔可以繼承另一個 struct 或者 class——struct 喺繼承呢件事上係隱式 sealed 嘅。但佢哋可以實作 interface：

public readonly record struct AudioLevel(double Rms, bool IsSpeech) : IComparable<AudioLevel>
{
    public int CompareTo(AudioLevel other) => Rms.CompareTo(other.Rms);
}

8. 動手練習

估下輸出 1：class 定 record equality

唔好即刻跑，先估下呢四句會印咩：

public class ChunkLabel
{
    public string Text = "";
}

public sealed record ChunkLabelRecord(string Text);

var a = new ChunkLabel { Text = "intro" };
var b = new ChunkLabel { Text = "intro" };

var ra = new ChunkLabelRecord("intro");
var rb = new ChunkLabelRecord("intro");

Console.WriteLine(a == b);
Console.WriteLine(ra == rb);

答案：False、True。a、b 係兩個獨立 new 出嚟嘅 ChunkLabel object，class 預設 == 比較嘅係「係唔係同一個 object」，內容一樣都唔算。ra、rb 就唔同：record 嘅 == 係編譯器自動生成嘅 value equality，逐個 property 比較，內容一樣就 True。

估下輸出 2：mutable struct 喺 foreach 入面 
public struct RawAudioLevel
{
    public double Rms;
    public bool IsSpeech;
}

var readings = new List<RawAudioLevel> { new RawAudioLevel { Rms = 0.01, IsSpeech = true } };

foreach (var reading in readings)
{
    reading.IsSpeech = false;
}

Console.WriteLine(readings[0].IsSpeech);

答案：True，唔係 False。RawAudioLevel 係 value type，foreach 入面嘅 reading 係 readings[0] 嗰份值嘅獨立複製；reading.IsSpeech = false 淨係改到 reading 呢個複製品，同 list 入面嗰個原本嘅值完全冇關係——呢個就係第 4 節提過嘅 mutable struct 陷阱，喺一個真正嘅 VAD gate 入面，呢個 bug 會令標記完全冇生效。

自己動手：由 mutable class 改做 immutable record

已經幫你喺 demo/csharp-practice/concepts/05-class-record-struct-practice.cs 準備咗 TODO 骨架，入面有一個設計錯咗嘅 mutable class：

public class LectureNoteDraft
{
    public string Title;
    public string Body;
}

LectureNoteDraft 概念上係一份「寫低咗就唔應該再喺原地被人靜靜雞改」嘅筆記草稿，但依家用緊 mutable class + public field，任何人隨時可以喺任何地方偷偷改咗個 Title 或者 Body，冇留低任何痕跡。你嘅任務：

  • 將 LectureNoteDraft 改寫做一個 sealed record，Title、Body 兩個屬性寫成 positional 或者 init-only 都可以（揀一種）；
  • 建立一個 draft instance；
  • 用 with-expression 產生一份改咗 Body 嘅新 copy edited，印出兩份，並印出 draft == edited。
cd demo/csharp-practice
dotnet run concepts/05-class-record-struct-practice.cs

答案：

public sealed record LectureNoteDraft(string Title, string Body);

var draft = new LectureNoteDraft("Week 1", "CAP theorem intro");
var edited = draft with { Body = "CAP theorem intro, revised after Q&A" };

Console.WriteLine(draft);
Console.WriteLine(edited);
Console.WriteLine(draft == edited);   // False，Body 唔同，value equality 判佢哋唔相等
