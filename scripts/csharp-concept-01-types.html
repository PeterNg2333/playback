0. 點解獨立一課？

型別（type）係 C# 入面最基本、但都最容易輕視嘅概念。表面睇淨係「畀個字加喺變數前面」，但背後決定咗：呢個值用幾多記憶體、會唔會溢位（overflow）、複製嗰陣係複製緊個值定係複製緊個參照（reference）、同埋 compiler 幾時可以幫你捉錯。呢頁會將快覽版本入面提過嘅型別逐個拆開，補返「點解」同「幾時揀邊個」，唔淨係「有邊啲」。

建議你已經做完 C#／.NET 零基礎教學，識基本嘅變數宣告、Console.WriteLine 同 if/else。呢頁唔會再由零教執行環境。

1. Static typing 係咩，點解重要

C# 係 statically typed 語言：每一個變數嘅型別喺 compile time（build 嗰刻，仲未 run）就已經固定咗，之後唔可以變做另一種型別。相反，Python 係 dynamically typed：一個變數今日可以裝 int，聽日執行到另一句就可以裝返 string，Python 唔會理你，一直到你真係用錯個值嗰刻先會喺 runtime 爆錯。

# Python：dynamically typed，呢句合法，但可能收埋 bug
duration = 14.8
duration = "fourteen point eight"   # 冇錯，但之後 duration * 2 會喺執行嗰刻先爆
// C#：statically typed，呢句喺 build 嗰刻已經報錯，唔使等 run
double duration = 14.8;
duration = "fourteen point eight";   // Compiler error: 不能將 string 轉成 double

TypeScript 企喺中間：你可以寫型別（同 C# 相似），但都可以用 any 或者索性唔寫（退返做 JS，同 Python 一樣冇保障）。C# 唔容許你「唔寫」——就算用 var，型別都仲係喺背後固定咗，只係唔使你手打出嚟（第 4 節詳解）。

點解呢樣值得學？Static typing 嘅代價係你要打多啲字；換嚟嘅著數係 compiler 可以喺你分享份 code 之前，就幫你捉到大量「呢個值型別根本唔啱」嘅錯——尤其係大型 codebase，呢類錯往往要到好耐之後先會喺 production 出事先發現。

2. 數值型別家族

C# 冇一個統一嘅「number」型別，而係按「要唔要小數」、「要幾大範圍」、「要唔要精準無誤差」分咗好幾種：

型別分類大約範圍幾時用
int整數約 ±21 億預設嘅整數型別，一般計數、index、迴圈變數
long整數約 ±922 京int 唔夠大先用，例如講課錄音嘅 chunk sequence 編號
short／byte整數細好罕用，通常係同底層檔案格式或者網絡協議夾嗰陣先用
float浮點（近似值）約 7 位有效數字好少用；記憶體敏感嘅圖形／遊戲運算先會揀
double浮點（近似值）約 15-16 位有效數字C# 小數嘅預設型別，一般科學計算、量度（例如 chunk 長度秒數）
decimal十進制（精準）約 28-29 位有效數字錢、發票、任何唔容許四捨五入誤差嘅計算

浮點數會有誤差，呢個唔係 bug：double／float 內部用二進制儲存小數，好似 0.1 呢類數其實冇辦法精準表示，所以先會有 decimal 呢個「肯犧牲少少範圍，換取完全準確」嘅選擇。

自己試試（唔使開新檔，直接睇輸出）
Console.WriteLine(0.1 + 0.2);                 // double：0.30000000000000004
Console.WriteLine(0.1m + 0.2m);                // decimal：0.3

Overflow：超過範圍會發生咩事？

C# 預設唔會幫你自動報錯，數值會「行完再由頭嚟過」（wrap around）：

int max = int.MaxValue;           // 2147483647
Console.WriteLine(max + 1);       // -2147483648，唔係報錯！

如果想喺 overflow 嗰刻即刻拋出例外，可以用 checked 區塊：

checked
{
    int max = int.MaxValue;
    Console.WriteLine(max + 1);   // 拋出 OverflowException
}

Lecture-note app 用 long 嚟裝 chunk sequence，就係因為三小時錄音可能產生成千上萬個 chunk，int 理論上夠用，但用 long 買個保險，唔使將來先擔心 overflow。

3. bool／char／string

bool：淨係得兩個值

bool isRecording = true;
if (isRecording)
{
    Console.WriteLine("錄緊音");
}

同 Python 一樣，C# 唔容許用 0／1 或者 null 當 bool 用（Python 3 都唔容許咁做，但 C 系語言以前可以）——一定要係 true 或者 false。

char：單一字元，用單引號

char grade = 'A';
Console.WriteLine(grade);          // A
Console.WriteLine((int)grade);     // 65，char 內部其實係一個 16-bit 數字（UTF-16 code unit）

char 用單引號 'A'，string 用雙引號 "A"——兩者唔可以交換，'AB' 會喺 build 嗰刻報錯（char 只可以裝一個字元）。

string：reference type，但表現似 immutable value

第 7 節會詳細解釋 reference type，但 string 有個特別之處要早啲知：C# 嘅 string 一建立咗就唔可以修改。任何「改動」string 嘅操作（.Trim()、.ToUpper()、字串相加）其實都係建立一個全新嘅 string，原本嗰個冇變過：

string original = "  cap theorem  ";
string trimmed = original.Trim();

Console.WriteLine(original);   // "  cap theorem  "（完全冇變）
Console.WriteLine(trimmed);    // "cap theorem"（呢個係新嘅 string）

常見迷思：好多初學者以為 original.Trim();（唔接返個結果）會改到 original。唔會——Trim() 冇改任何嘢，佢淨係計算出一個新 string 並 return 出嚟；如果你唔接住（original = original.Trim();），個結果就掉咗。

字串內插值（string interpolation）用 $"..."，同 TS 嘅 template literal `...`、Python 嘅 f-string 對應：

string lecturer = "Dr. Chan";
int slideCount = 42;
Console.WriteLine($"{lecturer} 用咗 {slideCount} 張 slide");

如果字串入面有好多反斜線（例如 Windows 路徑）或者要跨行，可以用 verbatim string（前面加 @）：

string path = @"C:\lectures\week1\audio.wav";   // 唔使打 \\ 逃逸
string normal = "C:\\lectures\\week1\\audio.wav"; // 意思一樣，但要逃逸

大量拼接字串（例如喺迴圈入面）：因為每次「修改」都會建立新 string，喺迴圈入面不斷 += 會製造好多用完即棄嘅中間字串，浪費記憶體同效能。如果要組合大量文字（例如逐行砌一份 transcript），應該用 System.Text.StringBuilder——呢個屬於效能優化話題，呢頁唔展開，記住個名先。

4. var：型別推斷，唔係「冇型別」

var 常被誤會成 JavaScript 嘅 var（動態、可以轉型別）。喺 C#，var 淨係叫 compiler 「你自己由等號右邊嗰個值，推斷返個型別出嚟」——型別喺 compile time 一樣係固定咗，同你手寫明個型別完全冇分別，淨係少打幾個字：

var sessionId = Guid.NewGuid();   // compiler 推斷：sessionId 係 Guid
Guid sessionId2 = Guid.NewGuid(); // 手寫型別，效果一模一樣

sessionId = "not a guid";         // Compiler error：sessionId 仍然係 Guid，唔係 string

用 var 有兩個規則要記住：

  • 一定要喺宣告嗰句同時畀初始值（var x; 唔合法，因為冇值就冇嘢好推斷）。
  • 只可以用喺本地變數（method 入面），唔可以用嚟宣告 class 嘅 field 或者 method 嘅參數／回傳型別。

幾時用 var，幾時寫明型別？

情況建議
var id = Guid.NewGuid();用 var——右手邊已經寫晒個型別名，寫多次冇意思
var count = 0;寫明 int count = 0; 更清楚——單睇 0 唔知係 int、long 定 double
var chunks = LoadChunks();要視乎 LoadChunks 個名夠唔夠清楚；如果唔清楚回傳緊咩，寫明型別幫讀者

簡單原則：如果右手邊已經好明顯睇到型別（好似 new LectureChunk(...)、Guid.NewGuid()），用 var；如果唔明顯（method 呼叫、算式），寫明型別對讀者更好。

對比 dynamic：C# 都有一個叫 dynamic 嘅關鍵字，先至係真係「放棄 static typing」——型別檢查延後到 runtime，行為好似 Python。呢個喺 lecture-note app 呢類專案幾乎用唔著，見到都應該當係特殊情況，唔係日常寫法。

5. Literal 寫法

Literal 即係你直接寫喺程式入面嘅值本身（例如 42、"hi"）。C# 有幾個方便嘅寫法：

long totalChunks = 1_000_000L;   // 底線分隔，方便閱讀大數字，compiler 會忽略底線
int flags = 0b_1010_0101;        // 二進制，前綴 0b
int color = 0xFF00A0;            // 十六進制，前綴 0x
double duration = 14.8;          // 冇 suffix，預設就係 double
float ratio = 14.8f;             // f suffix：float
decimal price = 14.8m;           // m suffix：decimal

Suffix（L／f／m）唔可以慳略：如果你想要一個 decimal 值，一定要寫 14.8m，唔係 14.8（嗰個預設係 double，會令你後面「double 賦值畀 decimal 變數」嗰句喺 build 時報錯，因為呢個係窄化轉換，第 6 節解釋）。

6. 型別轉換：implicit、explicit、Parse

Implicit conversion：安全、自動、唔會call underline call

如果轉換過程保證唔會蝕位（例如由細範圍轉去大範圍），compiler 會自動幫你轉，唔使你寫任何嘢：

int count = 42;
long bigCount = count;      // int -> long，安全，自動轉
double asDouble = bigCount; // long -> double，安全，自動轉

Explicit conversion（cast）：可能蝕位，要你明確話畀 compiler 知你知情

double duration = 14.8;
int seconds = (int)duration;   // 明確 cast，結果 14——小數部分直接斬咗（truncate），唔係四捨五入！

long bigNumber = 5_000_000_000;
int overflowed = (int)bigNumber;  // 明確 cast，但數值太大，結果會係一個冇意思嘅負數

Cast 唔等於四捨五入：(int)9.99 結果係 9，唔係 10——cast 純粹係「斬咗小數部分」。想真正四捨五入，要用 Math.Round(9.99)，或者下面提到嘅 Convert.ToInt32。

string ↔ 數值：Parse、TryParse、Convert

方法輸入唔啱格式時幾時用
int.Parse(text)拋出 FormatException你有把握輸入一定啱格式（少用）
int.TryParse(text, out value)唔拋錯，回傳 false處理用家輸入、設定檔呢類唔保證啱格式嘅來源（建議做法）
Convert.ToInt32(number)——（呢度係轉數值，唔係 parse string）由 double／decimal 轉做 int，並用四捨五入而唔係斬尾
 
Console.WriteLine((int)9.7);            // 9  （cast：斬尾）
Console.WriteLine(Convert.ToInt32(9.7)); // 10 （Convert：四捨五入）

bool ok = int.TryParse("abc", out int value);
Console.WriteLine($"ok={ok}, value={value}");  // ok=False, value=0（TryParse 失敗時 out 變數會係預設值）

《C# 中階銜接》第 6 節嘅 ParsePositiveInterval 就係用 int.TryParse 呢個 pattern，配合 throw 分開「格式錯」同「數值違規」兩種問題——依家你識咗 TryParse 點運作，返去睇會更易明。

7. Value type vs Reference type

呢個係 C# 對比 Python／JS 最唔同嘅地方之一：C# 嘅型別分兩大類，複製嗰陣嘅行為完全唔同。

類別代表賦值 b = a 之後
Value typeint、double、bool、char、struct複製一整份獨立嘅值，a、b 之後互不影響
Reference typestring、class、List<T>、陣列複製嗰個係「指去邊度」，a、b 依然指住同一份資料
 
// Value type：int
int a = 5;
int b = a;
b = 10;
Console.WriteLine(a);   // 5，a 完全冇受影響

// Reference type：List<int>（陣列型集合，第 3 步 List+LINQ 會再詳細教）
List<int> listA = [1, 2, 3];
List<int> listB = listA;
listB.Add(4);
Console.WriteLine(listA.Count);   // 4！listA 都變咗，因為 listA 同 listB 指緊同一份 list

你可以幻想 value type 好似「影印一份新嘅出嚟畀你」，reference type 好似「畀多一條路牌，指去同一間屋」——郁到嗰間屋，兩條路牌行過去都會見到新裝修。

string 本身係 reference type，但因為佢immutable（第 3 節提過，任何「修改」都係整返個新 string），所以喺日常使用上，你唔會遇到「兩個變數指住同一份、會互相影響」嘅意外——呢個係 C# 刻意嘅設計，等你唔使成日為 string 操心。

struct（好似 int）係 value type；class／record 係 reference type——呢個分別會直接影響你點揀 class 定 record 定 struct，詳情留喺《Class、Record、Struct》深入教學。

8. 動手練習

估下輸出 1：計算一段錄音嘅總長度

UI 想顯示「呢個 session 大約錄咗幾耐」——用 chunk 數量乘以平均長度粗略估算。唔好即刻跑，先估下呢三句會印咩，同埋 chunkCount 點樣參與埋呢條 double 運算：

int chunkCount = 12;
double averageSeconds = 14.8;

double estimatedTotalSeconds = chunkCount * averageSeconds;
Console.WriteLine(estimatedTotalSeconds);

答案：177.6。chunkCount（int）同 averageSeconds（double）相乘，兩邊型別唔同，compiler 會將 chunkCount implicit widening 做 double（第 6 節教過，安全、唔使你手寫 cast），成條 expression 嘅型別跟返 double。呢類「一個 count（int）乘一個量度值（double）」嘅計算，喺呢個 app 度（例如估算總錄音時長、預算 chunk 檔案大小）成日會用到。

估下輸出 2：倒數計時顯示緊幾多秒

錄緊音嗰陣，UI 想喺一個 chunk 錄完之前顯示「仲有幾多秒」。secondsRemaining 係一個 double（內部計時本身有小數），但 UI 淨係想顯示成一個整數秒。估下呢兩種轉法印咩，邊種對用戶顯示更加合理：

double secondsRemaining = 9.6;

int truncated = (int)secondsRemaining;          // cast：斬尾
int rounded = Convert.ToInt32(secondsRemaining); // Convert：四捨五入

Console.WriteLine(truncated);
Console.WriteLine(rounded);

答案：9、10。兩個都「啱」，但意思唔同：(int) cast 永遠向下斬尾，顯示「9 秒」代表「至少仲有 9 秒未錄完」，比較保守；Convert.ToInt32 四捨五入，顯示「10 秒」比較貼近實際餘下時間，但有機會令用戶以為仲有成 10 秒、其實得返 9.6 秒。呢種「揀邊種轉換」嘅決定，喺寫 UI 倒數呢類 code 成日要諗——唔淨係考機械式記住規則，仲要諗畀用戶睇嘅感覺。

自己動手：安全解析錄音長度

已經幫你喺 demo/csharp-practice/concepts/01-types-practice.cs 準備咗 TODO 骨架。目標：寫一個 static double? ParseDurationSeconds(string input) method——

  • 用 double.TryParse 嘗試將 input 轉做 double；
  • 轉唔到，或者轉到但係負數，回傳 null（double?，第 4 步 nullable 會再詳細教呢個寫法，依家可以照抄）；
  • 轉到而且係非負數，就回傳嗰個值。

喺 top-level statements 分別試 "14.8"、"-3"、"abc" 三個輸入，印出結果。

cd demo/csharp-practice
dotnet run concepts/01-types-practice.cs

答案：

Console.WriteLine(ParseDurationSeconds("14.8"));  // 14.8
Console.WriteLine(ParseDurationSeconds("-3"));    // （空白，null 印出嚟係空字串）
Console.WriteLine(ParseDurationSeconds("abc"));   // （空白）

static double? ParseDurationSeconds(string input)
{
    if (!double.TryParse(input, out double value))
    {
        return null;
    }

    return value >= 0 ? value : null;
}
