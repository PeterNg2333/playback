命名習慣：PascalCase 同 camelCase

C# 唔會強制你點命名，但成個生態系統（包括 .NET 官方 library）都跟同一套習慣，跟住做會方便自己同其他人睇：

  • PascalCase（每個字首字母大寫）：型別名、method 名、public property——例如 LectureChunk、NormalizeTranscriptAsync、Sequence。
  • camelCase（第一個字細楷，之後大寫）：本地變數、method 參數——例如 sessionId、lecturerName。

完整規則表（private field 用 _camelCase、constant 用 PascalCase 唔係 ALL_CAPS、acronym 大小寫）同好名/壞名對照，睇 《命名規範》深入教學。

Function／Method：C# 點樣寫一個函式

C# 入面唔叫 function，叫 method——概念同 TS 嘅 function、Python 嘅 def 一模一樣：畀個名一組步驟，之後隨時可以「叫」佢做嘢，唔使抄多次程式碼。

static int Square(int number)
{
    return number * number;
}

Console.WriteLine(Square(4));  // 叫（call）呢個 method，會印 16

逐個部分拆開睇（由左至右）：

部分呢個例子意思
修飾詞static下面解釋——依家可以當成「必寫嘅樣板」
回傳型別int呢個 method 執行完會俾返一個 int。冇嘢要俾返就寫 void（等於 TS 嘅 void、Python 冇 return 時嘅 None）
名Square叫佢嗰陣要用嘅名，習慣用 PascalCase
參數(int number)括號入面，每個參數都要寫明型別——同 TS 個 (n: number) 好似，但 C# 呢個位唔可以唔寫型別（Python 就完全唔使寫）
body{ return number * number; }大括號入面係實際執行嘅步驟；return 令 method 完結並交返個值

之後你會不斷見到 static async Task<string> NormalizeTranscriptAsync(string text) 呢類寫法，其實都係同一個樣式，只係加咗 async、回傳型別換成 Task<string>（第 5 步會解釋點解）。

static 代表呢個 method 屬於「呢個檔案／type 本身」，唔屬於某一個 object instance，所以唔使先 new 一個 object 先可以叫佢——同 Python module-level 嘅 def 或者 TS 頂層嘅 function 差唔多咁易用。喺 file-based app（好似依家啲練習檔）嘅 top-level statements 下面，輔助 method 通常都寫成 static。

ref／out／in 參數、optional parameter、named argument、params 陣列、overloading、local function、recursion，呢啲進階寫法留咗喺 《Method／Function》深入教學。

泛型 <T>：一個「型別入面嘅型別」佔位符

好快你會見到 List<LectureChunk> 同 Task<string>。角括號入面嘅 T 唔係固定嘅型別名，而係一個佔位符——用嗰陣填返實際型別：

List<int> numbers = [1, 2, 3];         // 一個裝 int 嘅 list
List<string> names = ["Ada", "Bo"];    // 一個裝 string 嘅 list
List<LectureChunk> chunks = [];        // 一個裝 LectureChunk 嘅 list

Task<string> 同理：唔係「一個叫 Task 嘅嘢加返個 string」，而係「一個將來會完成、並提供一個 string 結果嘅工作」——第 5 步 async/await 會再詳細講。如果你用過 TS 嘅 Promise<string> 或者 Array<T>，呢個諗法係一樣嘅：角括號入面填緊「呢個容器／工作實際處理緊咩型別」。

想自己寫一個泛型 method／class、識 where T : ... constraint，睇 《泛型》深入教學。

Class vs Record vs Struct：先知有得揀

零基礎教學未教過點自訂型別，落去下一步會直接用 record，所以先簡單分清三者：

關鍵字預設比較方式幾時啱用
classreference equality（同一個 object 先算 equal）有身分、會隨時間變化嘅嘢（例如一個 UI 上嘅 recorder controller）
recordvalue equality（property 值一樣就 equal）純資料、想 immutable——呢個 app 嘅 chunk／transcript／note 都啱
structvalue type，複製時整份 copy好細、好常用嘅值（例如座標），呢個 app 暫時用唔著

下一步就會實際用 record 嚟定義 LectureChunk。如果你用過 Python 嘅 @dataclass(frozen=True)，record 就係嗰個諗法——自動生成 __init__／__eq__，仲加埋 with 咁樣整 copy 嘅寫法；TS 冇原生對應，最接近嘅係 readonly interface 加手寫嘅 equality function。

呢張表淨係三行；constructor、init-only property、record struct、equality 底層原理（點解 plain struct 嘅 == 用唔到）、inheritance，全部喺 《Class／Record／Struct》深入教學。

喺一個新檔案（例如 demo/csharp-practice/00-function.cs）寫一個 static method 叫 IsLongChunk：接收一個 double durationSeconds，如果大過 10 秒就回傳 true，否則 false。喺 top-level statements 度分別用 5.0、14.8 試一次，並印出結果。

2. Record：定義一筆唔可以隨便變形嘅資料

Lecture-note app 入面，一段講課片段（chunk）一路都需要記住邊個 session、第幾段、內容係咩。呢種「以資料為主，唔想被人隨便改」嘅嘢，用 record 啱過用 class。

建立檔案demo/csharp-practice/01-record.cs
// Record 練習：LectureChunk 是一筆不可變的講課片段資料
var sessionId = Guid.NewGuid();
var draft = new LectureChunk(sessionId, 0, "  CAP theorem intro  ", 14.8);
var cleaned = draft with { Text = draft.Text.Trim() };

Console.WriteLine($"draft   = {draft}");
Console.WriteLine($"cleaned = {cleaned}");

var same = new LectureChunk(sessionId, 0, "CAP theorem intro", 14.8);
Console.WriteLine($"cleaned == same content -> {cleaned == same}");

public sealed record LectureChunk(
    Guid SessionId,
    long Sequence,
    string Text,
    double DurationSeconds);

注意 record 定義擺喺最尾。C# 規定 top-level statements（會執行嘅程式碼）要行先，record／class 呢類 type 定義要行後，唔可以擺中間。

dotnet run 01-record.cs

預期輸出

draft   = LectureChunk { SessionId = ..., Sequence = 0, Text =   CAP theorem intro  , DurationSeconds = 14.8 }
cleaned = LectureChunk { SessionId = ..., Sequence = 0, Text = CAP theorem intro, DurationSeconds = 14.8 }
cleaned == same content -> True

with 產生一份改咗 Text 嘅新 copy，唔會改到 draft 本身；兩筆 record 只要 property 值一樣就 ==，呢個叫 value equality，同 class 預設比較 reference 唔同。

自己試試：加一個 Language property

喺 LectureChunk 加一個 string Language，並喺建立 draft 時補一個值（例如 "yue"）。你會見到 compiler 即刻報錯，要求所有建立 LectureChunk 嘅地方都補呢個新欄位——呢個係 record 幫你喺 compile-time 抓漏，唔使等 runtime 先發現漏咗資料。

答案：

public sealed record LectureChunk(
    Guid SessionId,
    long Sequence,
    string Text,
    double DurationSeconds,
    string Language);

// 建立時要多傳一個參數：
var draft = new LectureChunk(sessionId, 0, "  CAP theorem intro  ", 14.8, "yue");

3. List + LINQ：由一疊 chunk 變成有次序嘅筆記

ASR 送返嚟嘅 chunk 未必跟次序到，中間仲可能有靜音（空白文字）。呢一步用 List<T> 裝住佢哋，再用 LINQ 一條 pipeline 過濾、排序、轉做顯示文字。

建立檔案demo/csharp-practice/02-list-linq.cs
// List<T> + LINQ 練習：由一疊 chunk 變成有次序、乾淨的筆記行
var sessionId = Guid.NewGuid();

List<LectureChunk> chunks =
[
    new(sessionId, 2, "Eventual consistency examples", 15.0),
    new(sessionId, 0, "CAP theorem intro", 14.8),
    new(sessionId, 3, "   ", 4.2),
    new(sessionId, 1, "Network partitions", 15.0),
];

var noteLines = chunks
    .Where(chunk => !string.IsNullOrWhiteSpace(chunk.Text))
    .OrderBy(chunk => chunk.Sequence)
    .Select(chunk => $"{chunk.Sequence + 1}. {chunk.Text}")
    .ToList();

Console.WriteLine($"input={chunks.Count}, useful={noteLines.Count}");
foreach (var line in noteLines)
{
    Console.WriteLine($"  {line}");
}

public sealed record LectureChunk(
    Guid SessionId,
    long Sequence,
    string Text,
    double DurationSeconds);
dotnet run 02-list-linq.cs

預期輸出

input=4, useful=3
  1. CAP theorem intro
  2. Network partitions
  3. Eventual consistency examples

留意輸入資料本身次序係亂嘅（2, 0, 3, 1），但 OrderBy 幫你按 Sequence 復原正確次序；空白嗰筆（sequence 3）畀 Where 篩走咗，所以 useful 得返 3 筆。

自己試試：加返一個 Reverse，由新到舊顯示

喺 OrderBy 後面加 .Reverse()，睇下輸出次序點樣變。諗下：如果係 OrderByDescending 呢，結果會唔會一樣？

答案：兩種寫法喺呢個例子結果一樣，但意思唔同——.OrderBy(...).Reverse() 係「排完序，再掉轉」；OrderByDescending(...) 係「一開始就由大到小排」。資料多嘅時候，直接用 OrderByDescending 更清楚，唔使多一步。

var noteLines = chunks
    .Where(chunk => !string.IsNullOrWhiteSpace(chunk.Text))
    .OrderByDescending(chunk => chunk.Sequence)
    .Select(chunk => $"{chunk.Sequence + 1}. {chunk.Text}")
    .ToList();

4. Nullable：講師姓名可能真係未有

錄音開始嗰刻，可能仲未知道講師係邊個。與其用空字串 "" 扮「未有」，C# 俾你喺 type 層面講明「呢個位可能冇值」。

建立檔案demo/csharp-practice/03-nullable.cs
// Nullable 練習：講師名稱同 slide 編號都可能「未有值」
string? lecturerName = null;
int? currentSlide = 12;

string lecturerLabel = lecturerName?.Trim() ?? "（未提供講師名稱）";
Console.WriteLine($"lecturer = {lecturerLabel}");
Console.WriteLine($"slide = {currentSlide ?? 0}");

lecturerName = "  Dr. Chan  ";
lecturerLabel = lecturerName?.Trim() ?? "（未提供講師名稱）";
Console.WriteLine($"lecturer (after set) = {lecturerLabel}");
dotnet run 03-nullable.cs

預期輸出

lecturer = （未提供講師名稱）
slide = 12
lecturer (after set) = Dr. Chan

string? 話俾 compiler 知呢個變數可能係 null；?. 只有喺唔係 null 先會執行後面（例如 .Trim()）；?? 提供 null 時嘅後備值。

自己試試：如果攞走 ?. 會點？

將 lecturerName?.Trim() 改做 lecturerName.Trim()（去咗個 ?），保持 lecturerName = null，再跑一次。

答案：程式會喺 runtime 拋出 NullReferenceException——因為冇咗 ?. 嘅安全檢查，程式會強行喺 null 上面呼叫 .Trim()。如果開咗 nullable 分析（#:property Nullable=enable，01-csharp-basics 有用），compiler 仲會喺 build 嗰陣already 用底線標黃提早警告你。

5. async / await：等 ASR 回應時唔好卡住成個程式

真正嘅 ASR 服務、Gemini、database 都要透過網絡等待。如果用一般 method 死等，成個程式（甚至成個 server）會卡住。async/await 令你可以「等緊嘅時候」畀其他嘢繼續行。

建立檔案demo/csharp-practice/04-async.cs
// async/await 練習：模擬等待 ASR 服務回應時，不卡住程式
Console.WriteLine("Sending transcript chunk to ASR (simulated)...");
string normalized = await NormalizeTranscriptAsync("  cap theorem intro  ");
Console.WriteLine($"normalized = {normalized}");

static async Task<string> NormalizeTranscriptAsync(string text)
{
    await Task.Delay(300); // 模擬等待 ASR / network 回應
    return text.Trim().ToUpperInvariant();
}
dotnet run 04-async.cs

預期輸出（第二行會停約 0.3 秒先出現）

Sending transcript chunk to ASR (simulated)...
normalized = CAP THEOREM INTRO

Task<string> 代表「將來會完成、並提供一個 string 嘅工作」。await 唔係「開新 thread」，而係話俾 compiler 知：呢度暫停返，等呢個工作完成先繼續行落去。

自己試試：同時處理多個 chunk

試吓將三個唔同文字用 NormalizeTranscriptAsync 分別處理，先用一個一個 await（順序等），再改用 Task.WhenAll 一齊等。留意邊個快啲。

答案：

Task<string> t1 = NormalizeTranscriptAsync("intro");
Task<string> t2 = NormalizeTranscriptAsync("network partitions");
Task<string> t3 = NormalizeTranscriptAsync("consistency");

string[] results = await Task.WhenAll(t1, t2, t3);
foreach (var r in results) Console.WriteLine(r);
// 三個 Task.Delay(300) 會「一齊等」，總時間大約仍然係 0.3 秒，
// 唔係 0.9 秒——呢個係 async 對 I/O-bound 工作嘅主要著數。

6. Error handling：分清「估到嘅壞輸入」同「真係意外」

錄音間隔呢類數值，用家／設定檔可能俾錯格式。呢一步示範點樣用 TryParse 處理估到嘅情況，用 throw／catch 處理違反規則嘅情況，並且淨係 catch 你識得處理嘅 exception type。

建立檔案demo/csharp-practice/05-error-handling.cs
// Error handling 練習：分清「可預期的壞輸入」同「真正意外」
Console.WriteLine(TryDescribe("5"));
Console.WriteLine(TryDescribe("-5"));
Console.WriteLine(TryDescribe("abc"));

static string TryDescribe(string input)
{
    try
    {
        int value = ParsePositiveInterval(input);
        return $"OK: interval = {value}";
    }
    catch (ArgumentOutOfRangeException exception)
    {
        return $"REJECTED (out of range): {exception.ParamName}";
    }
    catch (FormatException exception)
    {
        return $"REJECTED (not a number): {exception.Message}";
    }
}

static int ParsePositiveInterval(string input)
{
    if (!int.TryParse(input, out int value))
    {
        throw new FormatException("Interval must be a whole number.");
    }

    return value > 0
        ? value
        : throw new ArgumentOutOfRangeException(nameof(input), "Interval must be positive.");
}
dotnet run 05-error-handling.cs

預期輸出

OK: interval = 5
REJECTED (out of range): input
REJECTED (not a number): Interval must be a whole number.

兩個 catch 分別處理兩種完全唔同嘅問題：格式錯（唔係數字）同數值違規（唔係正數）。如果淨係用一個 catch (Exception) 全部吞晒，你會分唔清將來 AI server 之類嘅 code 應唔應該 retry。

自己試試：加一個 catch-all，睇下有咩後果

喺兩個 catch 之後，再加一個 catch (Exception exception) { return "UNKNOWN ERROR"; }，然後試吓傳一個會令 ParsePositiveInterval 拋出其他你冇特登處理嘅 exception（例如將 input 換做 null）。

答案：傳 null 會令 int.TryParse(null, ...) 內部拋出 ArgumentNullException，會被你新加嘅 catch-all 接住變成 "UNKNOWN ERROR"。呢個示範咗點解教材建議唔好隨便加 catch-all：佢會靜靜地吞咗你未預計到嘅錯，令你唔知程式其實已經收到不合法輸入（例如 caller 忘記檢查 null），問題會延後先浮現。

static async Task<string> NormalizeTranscriptAsync(string text)
{
    await Task.Delay(50);
    return text.Trim().ToUpperInvariant();
}

static int ParsePositiveInterval(string input)
{
    if (!int.TryParse(input, out int value))
    {
        throw new FormatException("Interval must be a whole number.");
    }

    return value > 0
        ? value
        : throw new ArgumentOutOfRangeException(nameof(input), "Interval must be positive.");
}
