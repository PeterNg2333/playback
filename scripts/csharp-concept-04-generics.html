0. 點解獨立一課？

泛型（generics）係 C# 入面其中一個對初學者最抽象嘅概念，但同時亦係你日後成日都會遇到嘅嘢——List<T>、Dictionary<TKey, TValue>、Task<T>，甚至你自己成日寫嘅 int?，背後全部都係泛型。快覽版本淨係話你「呢個係佔位符」，但冇教你點解要有呢樣嘢、同埋點自己寫一個。呢頁會由「冇泛型嘅世界有幾慘」講起，逐步教到你識自己寫泛型 method 同泛型 class。

建議你已經做完 C#／.NET 零基礎教學，同埋睇過 型別與變數深入教學（起碼識 value type vs reference type）。如果 method 嘅參數、回傳型別呢啲概念仲唔熟，建議先睇 Method／Function 深入教學。

1. 冇泛型會點？

C# 1.0（2002 年）其實冇泛型呢樣嘢。嗰陣如果想寫一個「裝任何型別都得」嘅集合，得一個方法：用 System.Collections.ArrayList，佢入面每一格都當係 object（C# 所有型別嘅共同祖先）嚟裝：

using System.Collections;

ArrayList untyped = new ArrayList();
untyped.Add(14.8);       // 將 double 裝落去，內部「包裝」（box）成 object
untyped.Add("oops");     // compiler 見到係 ArrayList，乜嘢型別都肯畀你放入去

double first = (double)untyped[0];       // 攞返嚟嗰陣要自己手動 cast 返做 double
double second = (double)untyped[1];      // 呢句 compile 到，因為 compiler 唔知 untyped[1] 實際係咩
                                          // 一 run 就會拋出 InvalidCastException：明明係 string，你話佢係 double

呢個例子暴露咗兩個問題：

  • 冇型別安全（type safety）：ArrayList 入面可以隨便混入任何型別，compiler 完全幫唔到手，攞出嚟嗰刻要自己 cast，cast 錯型別就要等 runtime 先爆 InvalidCastException——呢個係第 3 步「先 build 後 run」原則想避免嘅事，卻喺呢度發生埋。
  • Boxing 嘅效能代價：14.8 呢個 double 本身係 value type，直接存喺 stack／變數本身；但要塞入 ArrayList 呢類淨係識收 object（reference type）嘅容器，就要「包裝」（boxing）——喺 heap 度開一舊新記憶體，將個 double 值複製埋去，先至攞個 reference 存入 ArrayList。攞返出嚟再 cast 返做 double，仲要「拆返出嚟」（unboxing）。兩個動作都有額外記憶體同 CPU 開銷。

而家對比 List<double>——泛型集合：

List<double> typed = [14.8];
typed.Add("oops");   // Compiler error：不能將 string 引數轉換成 double

呢句喺 build 嗰刻已經報錯，你根本冇機會 run 到嗰句錯嘢。而且因為 List<double> 一早知道自己淨係裝 double，攞元素出嚟嗰陣唔使 cast，亦冇 boxing 開銷。

泛型嘅整個重點：喺唔犧牲「一個 method／class 可以重用喺唔同型別」呢個彈性嘅前提下，攞返型別安全——編譯時期捉錯，唔使等 runtime，亦唔使承受 boxing 嘅效能代價。ArrayList 依家已經幾乎冇人用，見到都應該直接改用泛型版本嘅集合。

2. 自己寫一個泛型 method

想像你要寫一個 method：「畀我一個 list，如果有嘢就攞第一個，冇嘢就用個 fallback 值」。如果冇泛型，你要為 int、string、LectureChunk 各寫一個幾乎一模一樣嘅 method，淨係型別唔同。泛型 method 可以令你淨係寫一次：

static T FirstOrFallback<T>(List<T> items, T fallback)
{
    return items.Count > 0 ? items[0] : fallback;
}

Console.WriteLine(FirstOrFallback(new List<int> { 1, 2, 3 }, 0));   // 1
Console.WriteLine(FirstOrFallback(new List<string>(), "none"));    // none

拆解一下呢個簽名：

  • <T> 寫喺 method 名FirstOrFallback後面，即係「宣告一個叫 T 嘅型別參數（type parameter）」——你可以叫佢 T、TItem，任何合法識別字都得，T 淨係慣例。
  • 宣告咗之後，T 就可以喺呢個 method 嘅參數（List<T> items、T fallback）同回傳型別（static T FirstOrFallback）度，當一個真正嘅型別名咁用。
  • 你唔使自己寫 FirstOrFallback<int>(...) 話畀 compiler 知 T 係咩——compiler 會由你傳入嘅引數（第一次係 List<int>，第二次係 List<string>）自動推斷（infer）出 T，呢個過程同 var 嘅型別推斷係兩回事，但諗法類似——都係 compiler 幫你計。

同一個 method body，第一次呼叫 T 變成 int，第二次變成 string——每次呼叫獨立決定，唔會混淆。呢個就係泛型 method 嘅重用性：邏輯淨係寫一次，型別安全就自動跟晒每種型別走。

3. 自己寫一個泛型 class／record

<T> 唔止可以擺喺 method 度，都可以擺喺 class／record／struct 個名後面。想像你想要一個「連埋捕獲時間嘅值」——唔理個值本身係咩型別，都想順便記低幾時攞到手：

public sealed record TimestampedValue<T>(T Value, DateTime CapturedAt);

var captured = new TimestampedValue<double>(14.8, DateTime.UtcNow);
Console.WriteLine($"{captured.Value} at {captured.CapturedAt:HH:mm:ss}");   // 14.8 at 09:15:32（時間會唔同）

var namedCapture = new TimestampedValue<string>("CAP theorem intro", DateTime.UtcNow);
Console.WriteLine(namedCapture.Value);   // CAP theorem intro

TimestampedValue<T> 呢個 record 一宣告好，入面嘅 Value property 就可以用 T 當係真正嘅型別咁寫——同第 2 節嘅泛型 method 一樣，用嗰陣要填實際型別（TimestampedValue<double>、TimestampedValue<string>），呢次 record 唔似 method 咁可以由引數推斷，因為構造子（constructor）以外冇引數可以睇——但正寫喺 new TimestampedValue<double>(...) 嗰句，<double> 都係一睇就知，唔算麻煩。

呢個諗法同《C# 中階銜接》教過嘅 record 完全接得上——TimestampedValue<T> 一樣有埋 record 嘅 with expression、value equality（第 3 個深入頁 Class／Record／Struct 會詳細講 equality），淨係多咗一個型別參數。

命名慣例：如果一個 class／method 有多過一個型別參數，慣例會用 T 開頭再加有意義嘅字，例如 Dictionary<TKey, TValue>——第 4 節會見到。單一型別參數就直接用 T。

4. 常見泛型集合

.NET 內建咗幾個好常用嘅泛型集合，全部喺 System.Collections.Generic 命名空間：

型別特性例子
List<T>有次序、可以動態加減嘅陣列型集合List<LectureChunk> chunks = []; chunks.Add(chunk);
Dictionary<TKey, TValue>用 key 快速查值，例如用 session id 搵返嗰個 chunkDictionary<Guid, LectureChunk> bySession = []; bySession[chunk.SessionId] = chunk;
Queue<T>FIFO（先入先出），啱用嚟排隊等處理Queue<LectureChunk> pendingUpload = []; pendingUpload.Enqueue(chunk);
HashSet<T>淨係裝唔重複嘅值，查「有冇喺入面」好快HashSet<string> seenSessionIds = []; seenSessionIds.Add(sessionId.ToString());

四個都係同一個諗法嘅唔同變奏：用 <T>（或者 <TKey, TValue>）話畀 compiler 知呢個容器實際裝緊咩型別，之後 compiler 就會喺你加錯型別、或者攞出嚟當錯型別用嗰陣，喺 build 時捉到你。揀邊個，睇你需要嘅存取方式：要順序遍歷用 List<T>，要用 key 查就用 Dictionary，要排隊處理用 Queue<T>，要快速判斷「見過未」用 HashSet<T>。

5. Constraints：限制 T 可以係咩

預設情況下，T 可以係任何型別——但正正因為咩都得，compiler 唔知道 T 實際上有咩 method 可以用，所以你喺 method body 入面淨係可以對 T 做所有型別都共通嘅事（例如 .ToString()、賦值、傳嚟傳去）。如果想寫一個「攞兩個 T，比較邊個大」嘅 method，就要話畀 compiler 知：T 一定要係「識比較自己」嘅型別，用 where 子句加 constraint：

static T Max<T>(T first, T second) where T : IComparable<T>
{
    return first.CompareTo(second) >= 0 ? first : second;
}

Console.WriteLine(Max(3L, 12L));     // 12，比較兩個 chunk 嘅 Sequence（long）
Console.WriteLine(Max(14.8, 9.2));   // 14.8，比較兩個 chunk 嘅 DurationSeconds（double）

where T : IComparable<T> 話畀 compiler 知：「呢個 method 淨係接受有實作 IComparable<T> 呢個 interface 嘅型別」——int、string、double 呢啲內建型別全部都有實作，所以先可以喺 body 入面安心叫 first.CompareTo(second)：冇呢個 constraint，compiler 唔會畀你叫 .CompareTo，因為佢唔保證任意型別 T 一定有呢個 method。

其他常見嘅 constraint：

寫法意思
where T : classT 一定要係 reference type（唔可以係 int、struct 呢類 value type）
where T : structT 一定要係 value type
where T : new()T 一定要有一個 public、冇參數嘅構造子，等你喺 method 入面可以寫 new T()
where T : IComparable<T>T 一定要實作咗指定嘅 interface（呢度係「識比較自己」）

Constraint 唔係必需，但一旦你嘅泛型 method／class 需要對 T 做啲「唔係所有型別都識」嘅操作，就要用 constraint 話畀 compiler 知——換嚟嘅係 compiler 幫你保證，任何人用呢個泛型嗰陣，傳入嘅型別一定符合要求，唔會漏咗某個型別冇實作而 runtime 先爆。

6. Task<T> 同 Nullable<T> 都係泛型

你可能未為意，但《C# 中階銜接》已經教過嘅兩樣嘢，其實一早就係泛型：

Task<T>：「將來會有一個 T 型別嘅結果」

第 5 步 async/await 教過 static async Task<string> NormalizeTranscriptAsync(string text)——Task<string> 唔係一個獨立嘅「async 專用型別」，而係一個泛型 class Task<T>，代表「一個將來會完成、並提供一個 T 型別結果嘅非同步工作」。T 填 string，就係「將來會有個 string」；如果 method 淨係要做嘢、唔需要回傳值，就用冇型別參數嘅 Task（唔泛型嗰個版本）。

int?：其實係 Nullable<int> 嘅簡寫

int? 呢種問號寫法，只不過係 Nullable<int> 嘅 syntactic sugar（語法糖）——兩句寫法意思完全一樣：

int? maybeSlide = 12;
Nullable<int> sameThing = 12;   // 同一句嘢，淨係寫法唔同

Nullable<T> 本身有個 constraint：T 一定要係 struct（value type）——呢個亦解釋咗點解 string? 唔係用緊 Nullable<T>：string 本身已經係 reference type，一早就可以係 null，string? 嗰個問號淨係 nullable reference type annotation，同 Nullable<T> 係兩回事。

睇返先前學過嘅嘢：依家你識咗泛型嘅運作，返去睇 List<LectureChunk>、Task<string>、int? 呢類寫法，應該會有種「原來一直都係同一件事」嘅感覺——呢個先係泛型最大嘅價值：一套諗法，貫穿成個 .NET 生態。

7. 動手練習

估下輸出 1：Max<T> 用嚟揀最新／最長嘅 chunk

唔好即刻跑，先估下呢兩句會印咩——同一個泛型 Max，一次用嚟揀 Sequence 較大（即係較後）嗰個 chunk，一次揀 DurationSeconds 較長嗰個：

static T Max<T>(T first, T second) where T : IComparable<T>
{
    return first.CompareTo(second) >= 0 ? first : second;
}

Console.WriteLine(Max(3L, 12L));
Console.WriteLine(Max(14.8, 9.2));

答案：12、14.8。第一次呼叫 T 推斷做 long，12.CompareTo(3) 係正數，回傳 12——如果呢兩個數係兩個 chunk 嘅 Sequence，代表揀咗較後嗰個。第二次 T 推斷做 double，回傳較大嗰個 14.8——如果係 DurationSeconds，代表揀咗錄得較耐嗰個 chunk。兩次用同一個 method，type 完全唔同，全靠 constraint 保證兩種型別都識 CompareTo，唔使為 Sequence 同 DurationSeconds 各寫一個「揀大嗰個」嘅 method。

估下輸出 2：List<T> 唔畀你亂放型別

如果你試住編譯呢句（chunkDurations 本來想儲一堆 chunk 嘅 DurationSeconds）：

List<double> chunkDurations = [14.8, 15.0];
chunkDurations.Add("oops");

會發生咩事？同第 1 節嘅 ArrayList 例子（untyped.Add("oops") 之後攞出嚟先 InvalidCastException）比較。

答案：呢句根本編譯唔到——Compiler error: 引數 1: 無法從 "string" 轉換為 "double"，你連 run 都 run 唔到。同 ArrayList 果邊完全唔同：ArrayList 因為冇型別資訊，錯誤延遲到你攞出嚟做 cast 嗰刻先喺 runtime 爆；List<double> 因為有型別資訊，錯誤喺你打錯嗰句、仲未 build 完，就已經浮返出嚟。如果 chunkDurations 之後要拎去做 Sum()、Average() 呢類計算，你會好慶幸個錯誤係喺 build 時已經爆，而唔係等到 lecture 錄緊一半、程式先 crash。

自己動手：一個攞唔到就用預設值嘅泛型 lookup helper

第 4 節提過用 Dictionary<Guid, LectureChunk> 嚟用 session id 搵返個 chunk——但如果嗰個 id 根本唔存在（例如前端傳錯、或者仲未收到嗰個 chunk），lookup[id] 會直接拋 KeyNotFoundException，成個 app 死畀你睇。已經幫你喺 demo/csharp-practice/concepts/04-generics-practice.cs 準備咗 TODO 骨架。目標：寫一個 static TValue GetOrDefault<TKey, TValue>(Dictionary<TKey, TValue> lookup, TKey key, TValue fallback) method——

  • 用 lookup.TryGetValue(key, out var value) 嘗試攞值；
  • 攞唔到就回傳 fallback，唔好拋錯；
  • 試用喺兩種完全唔同嘅 Dictionary：一個 Dictionary<Guid, LectureChunk>（搵一個唔存在嘅 session id），一個 Dictionary<string, double>（搵一個唔存在嘅語言代碼嘅預設 chunk interval），證明同一個 method 兩種 key／value 型別組合都用得。
cd demo/csharp-practice
dotnet run concepts/04-generics-practice.cs

答案：

var bySession = new Dictionary<Guid, LectureChunk>();
var knownId = Guid.NewGuid();
bySession[knownId] = new LectureChunk(knownId, 0, "CAP theorem intro", 14.8);

var missingId = Guid.NewGuid();
var placeholder = new LectureChunk(missingId, -1, "(chunk not received yet)", 0);

Console.WriteLine(GetOrDefault(bySession, knownId, placeholder).Text);    // CAP theorem intro
Console.WriteLine(GetOrDefault(bySession, missingId, placeholder).Text);  // (chunk not received yet)

var chunkIntervalByLanguage = new Dictionary<string, double> { ["yue"] = 12.0 };
Console.WriteLine(GetOrDefault(chunkIntervalByLanguage, "yue", 15.0));  // 12
Console.WriteLine(GetOrDefault(chunkIntervalByLanguage, "en", 15.0));   // 15，"en" 唔存在，用返 fallback

static TValue GetOrDefault<TKey, TValue>(Dictionary<TKey, TValue> lookup, TKey key, TValue fallback)
{
    return lookup.TryGetValue(key, out var value) ? value : fallback;
}

public sealed record LectureChunk(Guid SessionId, long Sequence, string Text, double DurationSeconds);

同一個 GetOrDefault<TKey, TValue>，一次用喺 <Guid, LectureChunk>，一次用喺 <string, double>——呢個先係泛型 lookup helper 應該有嘅樣：唔使為每一種 Dictionary 組合各寫一次「搵唔到就用預設值」嘅邏輯。
