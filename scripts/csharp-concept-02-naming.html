一個好名，點樣改？

《C# 中階銜接》第 1 節淨係夠篇幅提一句「PascalCase 同 camelCase」；呢頁將命名規範呢部分拆出嚟，補齊完整規則、acronym 大小寫呢類最易錯嘅細節，同「點解要咁改」嘅原因。命名唔係美觀問題——跟錯規範，其他人（同幾個月後嘅你自己）睇 code 會慢好多，甚至以為兩個名代表緊唔同嘅嘢。

0. 點解獨立一課？

C# 唔會強制你點命名——compiler 唔理你叫個變數 x 定係 lectureChunk，兩句都一樣可以 build 到、run 到。但成個 .NET 生態系統（BCL、你用緊嘅 NuGet package、其他人寫嘅 code）都跟同一套命名慣例，跟住做有兩個實際著數：第一，你睇一個名嘅大小寫，就已經知佢係 type 定係本地變數，唔使打開定義去確認；第二，你自己嘅 code 同其他 C# 開發者嘅 code 睇落一致，減低溝通成本。呢頁會將呢套慣例逐一講清楚，唔淨係「型別 PascalCase、變數 camelCase」咁概括。

建議你已經做完 C#／.NET 零基礎教學，識基本嘅 class、method、變數宣告。呢頁唔會再由零教執行環境。

1. PascalCase vs camelCase 基本規則

C# 命名幾乎全部圍繞呢兩種寫法：

  • PascalCase：每一個字嘅首字母都大寫，包括第一個字。例如 LectureChunk、SessionId、NormalizeTranscriptAsync。
  • camelCase：第一個字全部細楷，之後每一個字嘅首字母大寫。例如 sessionId、lecturerName、durationSeconds。

兩者嘅分別淨係「第一個字嘅首字母大寫定細楷」，之後嘅字兩種寫法都係大寫開頭。分得清呢個之後，剩低嘅問題就係：邊種識別字（identifier）用邊種寫法？

識別字種類寫法例子
Class／Record／Struct／Interface 名PascalCaseLectureChunk
Method 名PascalCaseNormalizeTranscriptAsync
Public propertyPascalCaseSessionId
本地變數／method 參數camelCasesessionId

下一節會將呢張表擴展到全部識別字種類，包括 private field、常數、enum 呢類容易搞錯嘅。

2. 完整命名規則表

以下呢張表涵蓋日常寫 C# 會遇到嘅所有識別字種類：

識別字種類寫法例子
Class／Record／StructPascalCaseLectureChunk
InterfacePascalCase，加 I 前綴IComparable
MethodPascalCaseNormalizeTranscriptAsync
Public propertyPascalCaseSessionId
Public field／const fieldPascalCaseMaxChunkSeconds
Private fieldcamelCase，加底線前綴 __sessionId
本地變數／method 參數camelCasesessionId
常數（const／static readonly）PascalCase（唔係 ALL_CAPS）public const int MaxRetryCount = 3;
Enum 型別同成員PascalCaseenum RecordingState { Idle, Recording, Paused }
NamespacePascalCase，用點分隔，對應資料夾結構Playback.Audio
Async methodPascalCase，加 Async 後綴NormalizeTranscriptAsync
Generic 型別參數T 前綴；單一個就叫 T，多個就 TKey／TValueDictionary<TKey, TValue>
Boolean 變數／propertycamelCase／PascalCase，加 Is／Has／Can 前綴IsRecording、HasTranscript

常見迷思：常數唔係 ALL_CAPS。如果你識 C、Java 或者好多其他語言，會習慣常數用全大寫加底線，例如 MAX_RETRY_COUNT。C# 唔跟呢個慣例——const 同 static readonly 一樣用 PascalCase，同其他 public 成員睇齊：

// 啱：C# 慣例
public const int MaxRetryCount = 3;

// 唔啱：呢個係 C／Java 嘅慣例，唔係 C# 嘅
public const int MAX_RETRY_COUNT = 3;

Generic 型別參數例子：

// 單一個型別參數，叫 T
class Cache<T> { }

// 多個型別參數，用有意思嘅名加 T 前綴
class Dictionary<TKey, TValue> { }

Boolean 命名例子：

bool isRecording = true;      // 本地變數：camelCase + Is 前綴
public bool IsRecording { get; set; }   // Public property：PascalCase + Is 前綴
public bool HasTranscript { get; set; }
public bool CanRetry { get; set; }

3. Acronym 大小寫規則（最易錯嘅細節）

當一個識別字入面包含縮寫（acronym，例如 HTTP、XML、JSON、IO、UI），大小寫要跟一條特別規則，唔係跟返 acronym 本身嘅大寫：

Acronym 長度PascalCase 入面點寫例子
2 個字母兩個字母都大寫IOException、UIElement
3 個字母或以上淨係第一個字母大寫，其餘細楷HttpClient（唔係 HTTPClient）、XmlWriter（唔係 XMLWriter）、JsonSerializer（唔係 JSONSerializer）

最常見嘅錯：好多人由其他語言或者由「acronym 應該全部大寫」呢個直覺出發，寫成 HTTPClient、XMLWriter、JSONSerializer。呢啲喺 C# 慣例入面全部錯——.NET BCL 本身嘅類別就係 HttpClient、XmlWriter、JsonSerializer，三個字母或以上嘅 acronym 淨係大寫第一個字。

喺 camelCase（acronym 出現喺識別字開頭）嗰陣，規則對應咁調：2 個字母嘅 acronym 全部細楷，3 個字母或以上就淨係第一個字母細楷：

// 2 個字母 acronym（IO）：PascalCase 兩個字母都大寫，camelCase 兩個字母都細楷
class IOStream { }
var ioStream = new IOStream();

// 3 個字母或以上 acronym（HTTP）：PascalCase 淨係首字母大寫，camelCase 淨係首字母細楷
class HttpClient { }
var httpClient = new HttpClient();

Acronym 出現喺識別字中間或者尾段（唔係開頭）嗰陣，兩種寫法都跟返「3 個字母或以上淨係首字母大寫」嘅規則，同開頭嗰個字係咪 acronym 冇關係：

// jsonSerializer：json 喺開頭，camelCase 淨係首字母細楷（因為 JSON 係 4 個字母）
var jsonSerializer = new JsonSerializer();

// lectureIoAdapter：Io 喺中間，一律跟「首字母大寫、其餘細楷」
class LectureIoAdapter { }

4. Private field 慣例：_camelCase

喺一個 class 入面，private field（即係淨係嗰個 class 自己用嚟儲存資料，唔對外公開嘅變數，又叫 backing field）跟一個特別慣例：camelCase 之前加一個底線 _。呢個係現時 .NET 社群嘅主流寫法（.NET runtime 本身、ASP.NET Core 呢類官方 codebase 都跟緊）。

public class RecordingSession
{
    private bool _isRecording;

    public bool IsRecording => _isRecording;

    public void Start()
    {
        _isRecording = true;
    }

    public void Stop()
    {
        _isRecording = false;
    }
}

底線前綴嘅著數：喺 method 入面一眼就分得出邊個係 field（_isRecording），邊個係本地變數或者參數（isRecording）——唔使加 this. 都唔會撞名。

Record 通常唔使呢個慣例。如果你用 positional record（例如 public record LectureChunk(Guid SessionId, long Sequence, string Text, double DurationSeconds);），property 係 compiler 幫你自動生成，背後雖然都有 backing field，但你唔會、亦唔使自己攞到嗰個 field 嚟寫——你成日都係直接用 chunk.SessionId 呢種 public property。_camelCase 呢條規則淨係用喺你自己手寫、需要喺 class 入面操作嘅 private field。

5. 好名 vs 壞名

跟啱大小寫只係第一步，名本身有冇意思一樣重要。以下對比幾組常見嘅壞名同對應嘅好名：

壞名好名問題喺邊
string s;string lecturerName;s 完全冇透露呢個值代表咩，睇 code 嗰個要向上追蹤先知
int temp;int retryCount;temp 講緊「呢個變數係暫時嘅」，但冇講「暫時裝住咩」
class dataHolderclass LectureChunk兩個問題：大小寫錯咗（type 應該用 PascalCase），加上 dataHolder 太籠統，冇講呢個 class 裝緊邊種資料
bool flagbool isRecordingflag 冇講呢個 true/false 代表緊咩狀態；好嘅 bool 名應該似一句可以答「係」定「唔係」嘅問題
int usrCntint userCount唔清楚嘅縮寫（usr、cnt）慳唔到幾多字，但加重讀者嘅認知負擔

背後嘅原則：名要講呢個值「係咩」或者「做緊咩」，唔係講佢「點樣實作」。lecturerName 講緊呢個值代表講師個名；s 完全冇提供呢類資訊，逼讀者要睇埋周圍嘅 code 先明。

唔使 Hungarian notation。好耐之前有種寫法叫 Hungarian notation，會喺變數名前面加返個型別縮寫，例如 strName（string）、iCount（int）。C# 係 statically typed 語言（第一頁《型別與變數》教過），editor／IDE 隨時可以話你知一個變數嘅型別，所以呢種前綴喺 C# 完全冇需要，加咗反而令個名更長、更難讀。

// 唔使咁做：
string strLecturerName = "Dr. Chan";
int iRetryCount = 3;

// 應該咁做：型別由 IDE／compiler 負責，個名淨係負責講呢個值代表咩
string lecturerName = "Dr. Chan";
int retryCount = 3;

6. 動手練習

睇一睇：邊個啱？1——private field

一個 private field 裝住「錄音緊定未錄音」呢個狀態，以下邊個名最啱？

recording
_isRecording
IsRecording
_recording_state

答案：_isRecording。理由：（1）呢個係 private field，要跟 _camelCase 慣例，所以 recording（冇底線）同 IsRecording（PascalCase，通常留畀 public property）都唔啱；（2）_recording_state 用咗 snake_case，C# 完全唔用呢種寫法；（3）加埋 Is 前綴令個名清楚表達呢個係一個 boolean 問句「係咪錄緊音」，比純粹 _recording 更明確。

睇一睇：邊個啱？2——HTTP 相關嘅 class 名

要寫一個 class 負責用 HTTP 去攞 lecture materials，以下邊個名最啱？

HTTPMaterialFetcher
HttpMaterialFetcher
httpMaterialFetcher
HttpmaterialFetcher

答案：HttpMaterialFetcher。理由：HTTP 係 4 個字母嘅 acronym，喺 PascalCase 入面跟「3 個字母或以上淨係首字母大寫」嘅規則，寫成 Http，所以 HTTPMaterialFetcher 錯（全大寫）；httpMaterialFetcher 錯（class 名要用 PascalCase，唔係 camelCase）；HttpmaterialFetcher 錯（Material 呢個字冧咗做細楷，斷詞唔清）。

自己動手：幫個 record 改返啱名

已經幫你喺 demo/csharp-practice/concepts/02-naming-practice.cs 準備咗 TODO 骨架，入面有以下呢段用咗好差命名嘅 code：

record lc(Guid id, long seq, string txt, double dur);

var x = new lc(Guid.NewGuid(), 0, "CAP theorem", 14.8);
Console.WriteLine($"{x.seq}: {x.txt}");

你嘅任務：跟返呢頁教嘅規則，將個 record 型別名同全部 property 改做符合 C# 慣例嘅名，再更新埋用到嗰段 code：

  • lc（型別名）→ LectureChunk：擴充清楚，PascalCase；
  • id → SessionId：講清楚呢個 Guid 係邊個 session 嘅 id；
  • seq → Sequence：擴充唔清楚嘅縮寫；
  • txt → Text：擴充唔清楚嘅縮寫；
  • dur → DurationSeconds：講清楚單位係秒，唔淨係「一個 duration」。

保持成個型別係 sealed record，並用改咗名之後嘅 property 印返同一段資訊。

cd demo/csharp-practice
dotnet run concepts/02-naming-practice.cs

答案：

sealed record LectureChunk(Guid SessionId, long Sequence, string Text, double DurationSeconds);

var chunk = new LectureChunk(Guid.NewGuid(), 0, "CAP theorem", 14.8);
Console.WriteLine($"{chunk.Sequence}: {chunk.Text}");

留意 chunk 呢個本地變數名都由冇意思嘅 x 改咗做 chunk——雖然題目冇明文要求，但呢個都係跟返第 5 節「名要講呢個值係咩」嘅原則：x 冇透露任何資訊，chunk 即刻話你知呢個變數裝住一個 lecture chunk。
